# 真实任务窗口 · 四项成本记录表

> 类型：指南 + 记录模板。配合 [PLAN-gui-real-task-window.md](PLAN-gui-real-task-window.md) 的操作脚本使用：**照原脚本跑任务，额外用这张表记四个数**。
> 同一张表以后用于 plain-v1 对比：先在 main 上跑一次得到**基线**，plain-v1 的 P1 界面接上真实运行后，用**同一个任务、同一套脚本**再跑一次，两列对比。

## 为什么要记这四个数

GUI 好不好用，最终看的是"人为它付出的成本"。截图和感觉说不清楚，这四个数能比较：

| # | 成本 | 一句话定义 | 越小越好 |
|---|---|---|---|
| 1 | 看懂状态耗时 | 看一眼屏幕，到能说出"它在做什么 / 在等我什么 / 下一步是什么"用了几秒 | ✓ |
| 2 | 建任务填几项 | 从打开新建任务，到点「创建并启动」，一共动手填/选/粘了几处 | ✓ |
| 3 | 总等待 | 从「创建并启动」到可以开始验收，墙钟一共几分钟 | ✓ |
| 4 | 拒绝 / 要求调整 / 重来 | 三类介入各几次（脚本规定必做的那 1 次「要求调整」单独标注） | ✓ |

## 怎么量（不需要任何工具，手机秒表即可）

1. **看懂状态耗时**：在三个时刻各量一次 —— A. 任务刚开始运行、状态条出现时；B. 第一张审批卡出现时；C. 进入人工验收时。
   做法：先移开视线，按下秒表再看屏幕，能**说出声**三句话（在做什么 / 在等我什么 / 下一步）就停表。说不全或说错，记"未看懂"并写下卡在哪。
2. **建任务填几项**：每一个你**动过**的输入算 1 项（文本框、下拉、勾选、每一条检查命令各算 1）；只看没改的默认值不算，但在备注里写"看了 N 个默认值"。顺手记下从打开到点启动用了几分钟。
3. **总等待**：点「创建并启动」时看一眼钟，可以开始验收时再看一眼。另记"最长一次干等"（屏幕没变化、你也不知道要不要做什么）大概几分钟。
4. **介入次数**：每次点「拒绝」「要求调整」，或者放弃重开一个任务，各记 1 次。脚本第 3 节规定必做 1 次「要求调整」，记成"调整 1（脚本）"。

## 写进 `real-task-result.json` 的字段

原脚本第 5 节要求的 `real-task-result.json` 再加一段 `costs`（数值不确定就写 `null`，不要估一个好看的数）：

```json
{
  "surface": "main",
  "commit": "<当时的 commit>",
  "costs": {
    "statusUnderstandSeconds": { "running": 0, "firstApproval": 0, "acceptance": 0 },
    "statusNotUnderstood": [],
    "createFieldsTouched": 0,
    "createDefaultsReviewed": 0,
    "createMinutes": 0,
    "totalWaitMinutes": 0,
    "longestIdleWaitMinutes": 0,
    "interventions": { "reject": 0, "adjust": 1, "adjustScripted": 1, "restart": 0 }
  },
  "falseCompletion": false,
  "outOfScopeWrites": false
}
```

## 拿来做判断的规则（提前定好，避免事后找理由）

plain-v1 只有同时满足下面四条才算"值得换"：

1. 四项成本里**至少两项明显更好**（看懂状态少 30% 以上、填写项少 2 项以上、等待少 20% 以上、介入少 1 次以上，任选其二）；
2. 其余项**没有明显变差**（不差过 20%）；
3. **零假完成**；
4. **零越界写入**。

不满足就不换，或者只采纳更好的那部分。一次结果有偶然性：如果差距很小，再各跑一次再下结论。
