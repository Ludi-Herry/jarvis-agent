## 建议顺序与取舍总览

| 项 | 一句话价值 | 成本/风险面 | 建议 |
| --- | --- | --- | --- |
| ① GUI 模型配置 | 任务创建时不再受 CLI 单模型锁死 | 低-中；只读 provider 目录扩写 | 有第二个模型可用时立项 |
| ② worktree 同仓隔离 | 同仓库并行两任务不互相踩 | 中；隔离与清理纪律 | 真实出现同仓并行需求时立项 |
| ③ Skill/MCP 管理 | GUI 里看/开关技能与工具源 | 中；只读先行 | 遇到「不知道哪个 Skill 生效」再立项 |
| ④ 多 pane / 独立窗口 | 多任务同屏审阅 | 高；冻结布局第二大变化点 | 已签收 V1 阅读层先行缓解；确证不足再立 |
| ⑤ 受控浏览器 | Agent 自动开网页取证据 | 高；权限面扩大 | 真实验收需要网页证据时立项 |

## ① GUI 模型配置

- **瓶颈**：`/api/live/models` 当前只忠实输出一个真实模型（CLI 配置固定）；创建任务时不能按任务换模型/思考档。
- **做**：CLI config 提供多 provider 配置（或项目 `.jarvis/models` 白名单）→ GUI 创建面板模型下拉出现真实多档；合同 `model/thinking` 落 journal 与 resume 校验沿用批 2 §G 合同。**不做**：中途/队列级换模型（需明确真实合同，单独再议）；不虚构能力集。
- **验收**：创建面板下拉 = 真实配置集合；选定模型写入 journal；恢复时漂移即 409。
- **成本**：前端小改 + provider 目录读取；模型调用仍按既有预算窗口管理。

## ② worktree 同仓隔离并发

- **瓶颈**：批 3 的并发合同是「同工作区同一时刻 1 个运行任务」；同仓两任务并行被保守挡住。
- **做**：任务创建可选「在 worktree 里跑」：服务端 `git worktree add` 到 `data/gui-worktrees/<task-id>`，任务 cwd 指向 worktree，验收后由 Owner 决定合并/丢弃；清理命令显式存在。**不做**：自动合并、自动删 worktree、接管用户 git 历史。
- **验收**：同仓 A/B 并行各跑各的；基线/Diff 分属两个 worktree；取消/终态不残留未声明目录；进程被杀后重开如实列出残留。
- **成本**：中。新增一类目录生命周期与清理纪律；需要真实 git 操作的定向测试。

## ③ Skill / MCP 管理

- **瓶颈**：CLI/core 已有 SkillRegistry、Recall，GUI 无入口；用户无法确认当前任务装了哪些 Skill、来源是什么。
- **做**：先只读——证据抽屉新增「能力」页签：当前任务可见 Skill 清单（id/来源/描述/是否生效）、MCP 工具源（若配置）。**不做**：在线安装/编辑 Skill（写操作另立项）；不重开 `propose_skill`（AGENTS 已拍板 defer）。
- **验收**：清单与 CLI 实际加载一致；来源可点开看磁盘路径；空配置时诚实空态。
- **成本**：低-中；读现有注册表即可。

## ④ 多 pane / 独立窗口

- **瓶颈**：一次只能看一个任务的对话/成果；批 6 的待处理提示只解决「不漏审批」，不解决并排审阅。
- **做**：阅读层 V1 已签收并交付（批 8），已覆盖「大读」场景；真正剩下的诉求是**两个任务并排运行视图**。若立项：先出样稿（沿用批 8 流程），批准后再动 `wb-shell` 列模。**不做**：无限 pane、拖拽布局编辑器。
- **验收**：样稿签收 + 实现后两任务并排不互相抢占输入焦点/审批卡；中栏 610px 硬验收线双栏态另行约定。
- **成本**：高（布局冻结的第二大变化点）。建议：先观察 V1 阅读层 + 待处理提示在真实窗口够不够用，再决定。

## ⑤ 受控浏览器

- **瓶颈**：预览页签是「用户开给自己看」的 iframe，Agent 不能自己开网页取证据（截图、控制台、交互）。
- **做**：复用既有 `browser_smoke` 工具链，GUI 增加受控浏览器页签：Agent 申请 → 用户审批 → 截图/控制台证据进工具链（不进入完成授权链）；会话级 profile 隔离，不接日常 Chrome。**不做**：代理外站绕嵌入限制、无审批的自主浏览、跨站登录态搬运。
- **验收**：审批门齐全；证据留痕；外站策略沿用批 3 §C 的确认与失败诚实化。
- **成本**：高；权限面明显扩大，需独立安全评审。

## 立项方式

逐项批准格式：「立项 ③」即按上表「做/不做/验收」执行；要改范围先说。全部搁置也完全成立——条件项的意义就是等真实需求。
