## 1. 完成定义与边界

本计划中的 1:1 同时要求：① V13 讨论区的布局、主题、尺寸、状态与交互；② 每个可见且可点击的讨论区操作有真实后端事实或命令；③ 重启、断线、审批拒绝和失败后状态仍诚实；④ 任务、权限、完成授权继续由 Jarvis Runtime 掌握。不能用浏览器内存假数据、固定 `main`、虚构成员或“已保存”提示代替接入。V13 本身标为“未接入”的按钮，若要成为可用产品，须先补其行为合同；视觉相同不能算功能完成。

**纳入**：讨论区左栏、空态、页头、消息流、Composer、任务监控、右侧详情与快捷面板、讨论分支、设置入口，以及从这些入口打开的真实文件、Git、工具、团队、浏览器和终端能力。设计画布和作品编辑绝不混入 Jarvis。

**不以不存在的界面扩张 1:1**：云同步、多人共用、插件市场、模型议会在当前 V13 讨论区没有可执行流程；它们在 §3 逐项登记，若以后要做，必须另有产品定义和成本。V13 的“团队”指同一用户的多 Agent 协作，不等于多个人共享账户。当前 `AGENTS.md` 的“不新增 verifier / route / scheduler 抽象”和 `propose_skill` 延后继续有效。

旧 `V13-PARITY-GAP.md` 的 A/B/C 仅用于说明过去的接线难易；其“B 保留不可用、C 跳过”不再是本目标的验收规则。旧 P3 真实任务尚未通过 Owner 验收，不因本规划改写历史。实施前同步修订 `PRODUCT.md`、GUI 交接与执行合同中相冲突的阶段范围。

## 5. 架构改造顺序与停止点

1. **固定参考与合同**：冻结 V13 讨论区源码清单、状态截图和每个可点击控件；把样稿占位的预期真实行为写成验收场景。无合同的入口不以“先画个按钮”代替。
2. **拆分 GUI 宿主的单任务假设**：现在 `GuiSessionHost` 在构造时固定一个 `task`、共享 provider/policy，并由一次任务合同决定工具。改为 TaskRegistry + 每任务运行上下文；仍复用 `runGoal/runAgent`、EventBus、SessionStore、PermissionGate 和完成判定。不重写 Agent 核心。
3. **建立版本化读写接口**：Overview 用持久工作区/任务索引；Snapshot 仅投影该任务事实；所有命令返回可回读状态，SSE 重连用完整投影。任意文件、终端、浏览器和 MCP 不共享一个无边界的通用 `invoke`。
4. **先接真实事实，再打开界面入口**：Git、Hook、Skill、上下文、子智能体、文件和进程各自有来源与失效态。没有接好时开发态可显式禁用；最终 1:1 验收不得把禁用入口计为完成。
5. **扩展权限与恢复**：新能力各有 ProjectGrant/PermissionGate 的操作级授权、审计、断线和停止语义。并发、分叉、模型切换不得继承旧任务的授权或完成事实。
6. **最后做视觉贴合与真实场景验收**：同一批冻结样例比较 V13 与 Jarvis；用户完成新建、工作区切换、模型选择、审批、团队分派、浏览器、终端、文件、审阅、导出与恢复的实际操作。P3 旧失败保留，不用新试件改写。

分批建议：P0 参考冻结与验收合同 → P1 自由任务/工作区/索引 → P2 消息与只读投影 → P3 模型/团队/Skill/MCP → P4 文件/附件/浏览器/终端/Git 动作 → P5 元数据、讨论分支、设置、并发与侧边任务 → P6 视觉、可访问性、安全、重启与真实任务验收。每批先定义可观察终态，不在一个 Agent 回合中承诺全量完成。

## 6. 工作量与关键风险

假设一名熟悉本仓库的全职 TypeScript/React 工程师；单位为**人周**，不是自然周，也不含等待 Owner 视觉验收和真实模型预算批准。

| 工作 | 估计 |
| --- | ---: |
| P0 参考冻结与接口/状态合同 | 1–2 |
| P1 任务、工作区和持久索引 | 7–12 |
| P2 A 桶视觉交互及只读投影 | 6–10 |
| P3 模型、团队、Skill/MCP 与上下文 | 8–14 |
| P4 文件、附件、浏览器、终端和 Git 操作 | 9–16 |
| P5 并发、讨论分支、侧边任务、设置与生命周期 | 7–12 |
| P6 安全、回归、性能、响应式及真人验收准备 | 5–9 |
| **合计（未含风险预留）** | **43–75** |

建议另留 **20–30%** 用于跨能力耦合和真实运行缺陷，规划量级约 **52–98 人周**。两名工程师可并行 UI 与独立只读能力，但任务宿主、权限、恢复和并发是共享关键路径，不能直接把自然工期除以二。内置浏览器是否允许任意外站、侧边对话是否可调用 Agent、MCP 可接哪些服务器，以及提交/推送是否在 GUI 执行，会显著改变上界；在对应批次实施前固定这些行为合同。

云同步、多人、市场、模型议会及设计区不计入上述估计；如 Owner 后续另立这些产品，应单独报价与验收。

## 7. 最终验收门

- 讨论区源控件逐项追踪表：每个可见入口都能走到真实 API/Runtime 事实与失败态；A/B/C 的旧标签不能成为跳过理由。设计区元素标注排除。
- 任务、工作区、会话、设置、侧边记录及附件在重启后按合同恢复；审批、权限、完成授权、失败证据与历史 verdict 不因 UI 操作改变权威。
- 对并发写冲突、断线重连、审批过期、终端中止、浏览器导航、MCP 失联和附件拒绝各有真实路径验证；不靠静态试件替代。
- 工程门沿用项目现有 typecheck/lint/test/build，GUI 子包另跑既有门；UI 在冻结视口与真实运行现场截图交 Owner 视觉签收，独立安全/恢复审查完成后才称 1:1。
