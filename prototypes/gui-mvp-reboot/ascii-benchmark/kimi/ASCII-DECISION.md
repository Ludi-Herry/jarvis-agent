## 2. 终选：方向 A（对话主轴 + 左右固定证据栏）

A 唯一同时满足三条硬约束的方案：对话保持中央主要阅读路径；Diff/验证/未验证项常驻一栏、审阅零步可达；审批以「对话内嵌卡 + 顶条锚点」双通道持续可达，完成授权在顶条与右栏双钉。它兑现「系统承担复杂度」——左栏归组任务现场与工具，右栏归组证据，用户永远不拼日志。

拒绝 B 的原因：对话被压到下半区约 40% 高度，违背「对话必须保持主要阅读路径」；审批走 modal，做决定时要盖住现场，与「审批持续可达且不脱离上下文」冲突；1280 下上区三面板必须降格或横滚，适配成本最高。它的上区「任务现场」一屏概览值得吸收为 A 左栏的排序依据。

拒绝 C 的原因：审批卡与证据摘要随时间线滚动漂移，靠「钉在顶部」补丁维持可达性，状态一多吸顶位会互相争抢；Artifact 审阅必须开抽屉，对话与 Diff 无法并排对照，削弱了「产物承担最终检查」；完成授权只有顶薄条单点承载。它的系统归组手法（工具组卡、证据摘要卡）已被 A 的左右栏吸收。

## 4. 方向 A 规格

### 区域尺寸比例

- 1440×900：顶条 56px [F]；左栏 任务现场 300px（约 21%）；对话主区 740px（约 51%）；右栏 补丁与验证 400px（约 28%）；Composer 条 96px [F]。
- 1280×800：顶条 52px [F]；左栏 230px（约 18%）；对话 660px（约 52%）；右栏 390px（约 30%）；Composer 条 88px [F]。
- 对话主区在两个视口都守住 ≥50% 宽度，这是「对话主轴」的量化底线。

### 固定/滚动归属

- 固定：顶条（任务身份/状态/授权/控制）、底部 Composer 条、左右栏外框与栏目标题。
- 滚动：对话流 [↕]；左栏任务现场内容 [↕]；右栏证据区 [↕]；右栏「上下文」子区独立 [↕]；Diff 全文查看在右栏内 [↕][↔]。
- 审批卡随对话流滚动，顶条「需要审批」锚点 [1 click] 随时回跳。

### 首屏信息顺序

1. 顶条：任务 ID + 目标 → 阶段/进度 → 运行状态 + 完成授权 → 暂停/继续/终止/恢复。
2. 对话区：最新消息与「需要你处理」审批卡（当前阻塞动作）。
3. 右栏：Diff 摘要 → 验证状态 → 未验证项。
4. 左栏：范围/影响 → 工具执行 → 阶段检查点。

### 键盘焦点顺序

1. 审批卡操作组：允许一次 → 要求调整 → 拒绝（当前阻塞动作最先）。
2. Composer 输入框 → 发送 / 作为调整意见。
3. 顶条控制：暂停 → 继续 → 终止（需确认）→ 恢复。
4. 右栏：Diff → 验证 → 未验证项 → 上下文。
5. 左栏：Reasoning 折叠 → 工具条目 → 检查点。
6. 对话流消息区（历史回读）。

### 状态变化时哪些区域变

- 完成：顶条徽章「完成授权未授予」→「decideVerdict · verified（模拟）」；右栏验证区全项通过；审批卡折叠为一条已决记录留在对话流；Composer 保持可用。
- 运行失败：顶条状态 →「运行失败」，阶段停在失败检查点；右栏验证区标出失败项；审批卡转为失败语义并保留原始证据入口；左栏工具执行标出失败工具；Composer 保持可用，引导纠偏。
- 已暂停：顶条 →「已暂停」，「继续」高亮；三栏内容与滚动位置冻结保留；Composer 可用。
- 已终止：顶条 →「已终止」（经确认），「恢复」激活；对话与证据现场完整保留只读；Composer 保留，输入作为恢复后的新指令。
- 恢复：顶条 →「运行中」，从断点续跑；对话流追加一条恢复标记；工具执行从排队项继续。

## 5. 进入 HTML 实现必须验证的 5 条断言

1. 首屏可达性：1440×900 与 1280×800 两种视口下，不滚动即可同时看到审批操作组（允许一次/拒绝/要求调整）、Composer 输入框和终止按钮，且互不重叠。
2. 授权单一来源：顶条与右栏的完成授权徽章只由 decideVerdict 结果驱动；「允许一次」之后、聚焦测试通过之前，两个位置都仍显示「完成授权未授予」。
3. 审批三分支：允许一次 → apply_patch 进入执行且视图切向验证；拒绝 → 任务进入失败/受阻且 Diff 原始证据可回读；要求调整 → 现场保留且键盘焦点自动落入 Composer。
4. 暂停不丢现场：暂停再继续后，对话流、左栏、右栏三处滚动偏移与审批卡状态与暂停前完全一致。
5. 证据可回溯、错误显式降级：右栏每个聚合条目（Diff/验证/未验证项）一步跳回来源文件或测试输出；任一读取失败时该条目显示明确的降级态，绝不渲染空白或沿用旧数据。
