## Jarvis 重组原则

1. 参考只影响信息架构、状态组织、渐进披露和交互落点；Jarvis Runtime 继续拥有 Session、权限、工具副作用、Goal 与完成授权。
2. 三稿共用 Jarvis 自己的窄状态：消息、Reasoning 摘要、工具执行、审批、Artifact/Diff、验证结果、终局与恢复。
3. 官方 README/产品媒体中的能力保留“产品说明”标签；源码存在只证明实现路径，未在本机运行的体验不升级为端到端事实。
4. 找到支撑三种结构的证据后停止横向扩展；多 Agent、插件、模型路由、云协作与自我改进不进入 P1。
