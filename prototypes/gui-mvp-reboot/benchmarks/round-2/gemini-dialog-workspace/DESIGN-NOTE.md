# 设计说明 · Gemini Dialog Workspace

## 1. 结构与产品取舍
本稿确立纯正的「100vh 桌面分屏对话工作区」架构。左侧 55% 宽度为「对话主干 + 常驻 Composer」，右侧 45% 为「任务控制中心 + 实时 Artifact/Diff 审查面板」。页面坚决杜绝页面级纵向滚动（0 document scroll），所有长列表与代码浏览均在各自 pane 内部按需滚动。

## 2. v0 截图发现与 final 因果修正
- **发现 1 (空间分配失衡)**：v0 中左栏过宽（58%），右侧 Diff 面板在 1280×800 下被挤压，长代码行出现横向遮挡，代码可视高度受限。
  - **修正**：重构双栏比例为 55% : 45%，精简待审批卡片内边距，释放垂直高度给 Diff 查看器，使 17 行关键 Diff 与行号完整展示。
- **发现 2 (视觉符号不统一)**：v0 混用普通 Emoji（💡、⚙、🔒），在不同操作系统下字重与对齐杂乱，缺乏精密工作台质感。
  - **修正**：全面替换为轻量几何 SVG 矢量图标（Hexagon、Gate Lock、Shield、Terminal Glyph），统一 1px 细微高光与语义色辉光。
- **发现 3 (输入区与操作流紧凑度)**：v0 底部 Composer 快捷芯片占用整行高度，推挤了输入框区域。
  - **修正**：收紧 Composer Quick Bar 与底部 Meta Row，将输入、清空、快捷指令与回车指示器整合为一体化桌面胶囊。

## 3. 确定性断言与交互验证
- **滚动断言**：在 1440×900 与 1280×800 下，`scrollHeight <= innerHeight + 1` 均为 `true`，`scrollWidth <= innerWidth + 1` 均为 `true`。
- **交互回路**：完成「允许一次」→「运行 vitest」→「decideVerdict · verified（模拟）」全链路联动，支持「拒绝」、「要求调整」、「暂停/继续」、「终止/恢复」及底部 6 档场景预设切换。

## 4. 已知限制
- 当前为无 Runtime 的静态演示原型，所有文件 Diff 与单测结果均为内存模拟，不产生真实磁盘副作用。
