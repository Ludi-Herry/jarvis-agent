# DESIGN-NOTE · ZCode Round 3 · 「阶段跟随审阅面」

## 方向选择（详见 DIRECTION-NOTE.md）

三个内部方向：A 台账双栏（放弃：证据永远停在侧栏地位，静态堆叠是统计默认值）、**B 阶段跟随审阅面（选定）**、C 横向任务带（放弃：800px 高度下纵向三段挤压，浮层式 Artifact 违背持续可见）。B 的主张：对话与证据「一桌两椅」——左侧对话流承担持续交互（档案式条目 + 常驻 Composer），右侧审阅面随任务阶段重排注意力（等待决定 → 验证中 → 终局 · verified），消息内工具 chips 与审阅面联动。视觉语言为「工程档案纸」：暖纸底、墨色、发丝线、无阴影；朱红只用于人工闸门（待审批 / 确认终止 / 完成授权未授予）。参考锚点：结构主锚 Kun（证据围绕工作区）、交互辅锚 Tutti Control Center（待用户决定集中一处 + 独立 gate）；拒绝人格化陪伴装饰、Agent OS / 多人 / 云协作、四区 IDE 全景 / 模型路由。

## v0 问题（确定性审计 + 代码审查，非视觉模型验收——用户免除视觉验收环节）

1. **[交互组织]** `renderChat` 每次状态变化全量重建消息 DOM 并强制吸附底部，且 `rise` 入场动画对全部旧消息重放——用户上滚回读历史时会被任何状态变化拽回底部、整列消息闪烁。
2. **[交互组织 / 状态机]** 终止「确认终止？」的解除计时器混入通用 `S.timers`，会被暂停 / 继续的 `clearTimers()` 误清，armed 状态可能永久卡在「确认终止？」。
3. **[空间分配]** 1280×800 下审阅面内部恰好 **0px 余量**（overflowPx = 0）——文案稍长或系统字体缩放 125% 时，「验证」「未验证项」两节将掉出首屏折叠线。
4. **[工程]** HTTP 验收环境下 favicon 404 污染 console。

## 修改（v0 → final）

1. `renderChat` 增量化：仅当消息数增加时吸附底部并给最新一条加 `.fresh` 入场动画；状态刷新不再打断回读（实测：滚动置顶后触发暂停/继续，`scrollTop` 保持 < 60px）。
2. 终止确认计时器独立（`termTimer`），新增 `cancelArm()`：暂停 / 继续 / 恢复 / reset 时主动解除 armed。
3. 压缩审阅面垂直预算（review-head / scroll padding 与 gap、卡片 padding、factrow 行距），1280×800 下内容余量从 **0px → 41px**，四节全部留在首屏。
4. `<link rel="icon" href="data:,">` 消除 favicon 请求。

## final 证据（Playwright @ http://127.0.0.1:8931，与 file:// 同一份文件）

- **滚动断言**：1440×900 与 1280×800 均 `scrollHeight ≤ innerHeight+1` 且 `scrollWidth ≤ innerWidth+1`（页面级零溢出）。
- **首屏几何**：两档 viewport 下目标未截断、授权徽章右缘 1424/1264 在界内、终止按钮在界内、Composer 底边贴 viewport 底、审阅面四节（决定 / Diff / 验证 / 未验证）全部可见。
- **交互矩阵**（全部通过，页面内存状态）：暂停→已暂停→继续→运行中；终止两击确认（「确认终止？」→ 已终止，Composer 禁用，授权保持未授予）→ 恢复→运行中；允许一次→「已批准（模拟）」→ vitest 运行中→通过（模拟）→ 徽章翻转为「decideVerdict · verified（模拟）」+ 步进器「验证 · 通过」；拒绝→「已拒绝（模拟）」+ 步进器「受阻」+ 授权保持未授予；要求调整→建议 chip 填入 Composer→发送→「待审批 · 已按调整更新（模拟）」；「作为补充指令」发送→消息带「补充指令」标签；完整 Diff 一步展开（12 行演示行，标注模拟）/ 摘要含 +29 / −2；推理摘要折叠/展开；工具 chip 联动审阅面。
- **console**：修复后加载 0 error / 0 warning；页面内 error 捕获数组为空。
- **可达性静态项**：`:focus-visible` 焦点环存在、`prefers-reduced-motion` 媒体查询存在、全文字号最小 12px（DOM 实测）、状态均为「字形 + 文字」非仅颜色。
